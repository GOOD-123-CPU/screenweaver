# 架构总览

ScreenWeaver 采用「引擎 / 渲染层 / 配置」三层分离设计，目标是让**数据、布局、视觉、组件**四个关注点彻底解耦。

```
┌─────────────────────────────────────────────────┐
│                配置层（JSON）                     │
│   layout（栅格占位）+ components（组件声明）        │
│   sources（数据源）+ theme（主题）                 │
└──────────────────────┬──────────────────────────┘
                       │ validateSchema 校验
┌──────────────────────▼──────────────────────────┐
│                引擎层（src/engine）               │
│  registry     组件注册表：type 字符串 → Vue 组件    │
│  useSources   数据源池：static/http轮询/ws/mock    │
│  useScale     等比缩放：设计稿坐标 → 任意视口       │
│  chartPresets 图表预设：简写 → 完整 ECharts option │
│  mock         模拟数据生成器（12 种）              │
│  validate     Schema 运行时校验（零依赖）          │
└──────────────────────┬──────────────────────────┘
                       │ provide('sw-sources')
┌──────────────────────▼──────────────────────────┐
│              渲染层（ScreenRenderer）              │
│  装饰层 → Header → 12×12 CSS Grid → 注册组件分派   │
└─────────────────────────────────────────────────┘
```

## 关键设计决策

### 1. 为什么是 12×12 栅格而不是绝对定位？

绝对定位（x/y/px）在大屏工具里最常见，但换设计稿就要全部重排。12 列栅格是响应式布局的成熟范式（Bootstrap/Foundation 沿用多年），任何 1920×1080 的设计稿都可以按比例换算成栅格占位，且天然支持不同尺寸设计稿之间的迁移。

### 2. 为什么数据源与组件分离？

组件只声明「我要哪个 key 的数据」（`props.source`），不关心数据从哪来。这样：
- 开发期用 `mock` 源快速出效果
- 联调时把 `mock` 换成 `http`，组件零改动
- 实时场景换 `ws`，依然零改动

### 3. 为什么图表用「预设 + overrides 深合并」？

直接暴露完整 ECharts option 会让配置变成第二套代码；只给封闭预设又不够用。折中方案：预设覆盖 80% 的通用美感（配色随主题、坐标轴、tooltip），`overrides` 用深合并让用户精确改到任意层级（数组整体替换、对象递归合并），两层各司其职。

### 4. 注册表模式如何工作？

`registry: Map<string, Component>` 把配置里的 `type` 字符串映射到 Vue 组件。内置组件在应用启动时批量注册；业务方可以注册自己的组件而不需要改动引擎源码——这是开闭原则在大屏场景的落地。

### 5. 缩放适配策略

设计稿坐标（如 1920×1080）固定，运行时 `scale = min(vw/designW, vh/designH)`，居中偏移后整体 transform。这是多屏拼接、非 16:9 显示器场景下最稳妥的策略；不采納 vw/vh 流式布局是因为大屏元素间的精确对位需求远大于空间利用率。

## 数据流

```
schema.sources ──► useSources 激活 ──► reactive store（key → { data, updatedAt }）
                                            │
              ws 推送 / http 轮询 / mock 定时 ─┘ 持续更新 updatedAt
                                            │
             组件 watch(source.updatedAt) ───┘ 触发重渲染
```

`updatedAt` 时间戳是所有组件统一的刷新信号：数字翻牌器据此启动缓动，图表据此 setOption，表格据此重排——组件不需要知道数据是推送的还是轮询的。
